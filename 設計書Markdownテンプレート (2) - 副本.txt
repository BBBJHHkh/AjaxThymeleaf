# 設計書 Markdown 変換仕様：原文版 → 構造化版

> **位置付け（改訂、案A）**
>
> - **原文版**（`原文版/`）：唯一の事実源。Excel シートを原文のまま転記する。レイアウトを変更しない、省略しない、編集的な説明を加えない。
> - **構造化版**：派生的な作業用コピー。P0～P4 コード生成プロンプトの入力として使用する。本仕様に従い原文版から変換する。
> - 変換は追跡可能でなければならない。取捨選択はすべて変換ログ（`## 変換ログ`）に記録する。
> - 鉄則：変換ではいかなる文字内容も変更してはならない。空欄や欠落項目を推測で補完してはならない。
>
> 旧用途（本テンプレートで写真から直接転記する）は廃止した。新規ドキュメントはまず原文モードで転記し、本仕様に従って変換する。

---

## 一、変換ルール

### 1.1 シート → 章節マッピング

節タイトルは構造化版の番号を用い、内容は原文版の対応シート（原名）から取る。原文版にないシート（未撮影など）は対応箇所に「（原文版未収録）」と記載する。捏造してはならない。

**PL / BL：**

| 原文版シート（原名） | 構造化版章節 |
| ---- | ---- |
| 表紙 | ## 1. 表紙 |
| 改訂 | （あれば転記し、なければ未収録と記載する） |
| クラス定義 | ## 2. クラス定義 |
| 処理詳細01 ～ NN | ## 3. 処理詳細01 ～ NN（番号順） |

**OW：**

| 原文版シート（原名） | 構造化版章節 |
| ---- | ---- |
| データ定義 | ## 1. データ定義 |
| 画面遷移定義 | ## 2. 画面遷移定義 |
| サービス定義 | ## 3. サービス定義 |

**定数一覧：**

| 原文版シート（原名） | 構造化版章節 |
| ---- | ---- |
| 表紙 | ## 1. 表紙 |
| 改訂履歴 | ## 2. 改訂履歴 |
| 定数一覧 | ## 3. 定数一覧 |
| 別紙2_ソース | ## 4. 別紙2_ソース |

### 1.2 表列の取捨

- テンプレートで定義された列は必須列とし、テンプレートの順序で並べる。
- 原表にあってテンプレートにない列：情報量のあるものは「備考」列に統合する（原列名を明記）。全空の列は省略する。
- テンプレートにあって原表にない列：空列のまま残す（削除しない）。
- 省略した列はすべて変換ログに記録する。
- 本案件例：OW データ定義32列幅表 → No.／プロパティ名／日本語名／データ型／○マトリクス列を取る。フォーマット系、Validation子列などの全空列は省略する。

### 1.3 表外文字

- 行末バージョン注記：引数表の「バージョン」列は残す。処理内容の行単位注記は省略する（ログに記録）。
- ヘッダー・フッター、表外説明文：情報量のあるものは備考に入れる。

### 1.4 転記注記の扱い

- 原文版末尾の「転記注記」を構造化版本文に持ち込んでは**ならない**。
- コード生成に影響する疑義は、構造化版の対応箇所に「※要設計確認」と記載するか、P0チェック項目に転記する。転記先は変換ログに記録する。

### 1.5 セル結合

- 縦方向結合による空欄は原文のまま空欄とし、上下行の値で補完しては**ならない**。
- 本案件例：OW サービス定義第2行（doNoAction）の No.／コンポーネントID などの空欄は空白のままにする。

### 1.6 文字内容の鉄則

- いかなる文字も変更しない（検証済み訂正結論を含む。直接採用する）。
- 空欄や欠落項目を推測で補完しない。
- 「（判読困難）」マークは原文のまま残す。

## 二、変換ログ

変換のたびに構造化版末尾に付帯しなければならない（`## 変換ログ`）。記録内容：

```markdown
## 変換ログ

- 変換日：[ ]
- 入力（原文版ファイル）：[ ]
- 省略した列・注記：[ ]
- セル結合の扱い：[ ]
- 転記注記の影響項目の転記先（P0／設計確認／対応箇所記載）：[ ]
```

## 四、本案件で判明した注意点（ABCDEFG03W030）

転記・生成時に引っかかった点を記録。今後の案件でも同様の観点でP0チェックすること。

1. **変数表にない変数の参照**：処理内容で使われている変数が変数表に定義されていないことがある
   （例：PL searchGamenJudgeの遷移用Dto、PL initのWebDTO初期化部品、PL doNoActionの取得利用者チェック）。
   → 原文版に原文のまま記録し、P0で「未定義参照」として報告する。
2. **表記ゆれ**：同一概念の表記がPL/BLで異なることがある（例：JOCOMMUNina vs JOCOMNUina、
   アプリ情報エリアの「メンバー変数」vs「クラス変数」）。→ 変換時は原文ママ、P0で報告する。
3. **OWとBLの不整合**：BLが設定するDTOフィールドがOWのマッピングにないことがある
   （例：Select003DaoInDto.摘要番号、DoNoActionServiceOutDto.端末区分）。→ P0で報告する。
4. **比較リテラルと定数値の表記差異**：PLの分岐条件のリテラルとBLの定数値が微妙に異なることがある
   （例：PL「対象検索追加操作ガイド押下」vs BL「対象検索追加操作ガイド（マイページ検索）」（P0 C8））。→ 字面通り転記し、P0で報告する。
5. **DAOパッケージの欠落**：BLの呼出仕様にDAOのパッケージ記載がないことがある。
   → dao.dtoのパッケージから推定し、TODO化する。
6. **定数はDUMMY運用**：定数一覧Excelの実値が揃うまでは `JOCOMNConst.DUMMY_*` で生成し、
   実値確定後に置換する。置換手順は `JOCOMN定数一覧_DUMMY.md` 冒頭に記載。
